# Pathfinder 对话知识侧栏设计

## 目标

把聊天窗口右侧现有的待办栏改造成一个当前会话专属的咨询状态栏，固定包含“待办”“已知内容”“未知内容”三个区域。三个区域必须随用户回答、工具结果和待办进度实时同步，帮助学生看清 Agent 正在做什么、已经确认了什么、还缺什么关键信息。

本功能只维护当前聊天的临时咨询上下文，不自动写入学生长期记忆。长期记忆仍由现有记忆系统管理，只有用户明确确认的资料才能进入长期记忆。

## 交互与版式

- 右侧栏保持现有固定位置、收起按钮、完成数量和响应式行为。
- 展开状态下从上到下显示三个独立区域：
  1. “待办”：显示完整任务列表及 `pending`、`in_progress`、`completed` 状态。
  2. “已知内容”：以简短列表显示本次聊天中已经确认、且与当前目标相关的事实。
  3. “未知内容”：以简短列表显示会影响结论、规划或建议的待确认信息。
- 每个区域有独立标题、数量标记和内部滚动，分隔线与现有深色界面保持一致。
- 三个区域始终保留标题。列表为空时显示简短空状态，避免用户误以为侧栏加载失败。
- 待办全部完成时不再自动隐藏整个右侧栏；它可以自动收起，但用户仍可再次展开查看已知与未知内容。只有用户主动关闭后才隐藏本次快照。
- 中英文界面分别使用“To-dos / Known / Unknown”和“待办 / 已知内容 / 未知内容”。Agent 写入的条目必须匹配当前界面语言。

## 结构化咨询快照

扩展现有 `todo_write`，让一次成功调用成为右侧栏的单一规范快照：

```json
{
  "todos": [
    { "content": "核验本学期重要日期", "status": "in_progress" }
  ],
  "known": [
    "学生计划在 2026 Spring 选课"
  ],
  "unknown": [
    "尚未确认学生当前已完成的先修课程"
  ]
}
```

- `todos` 沿用现有结构和最多一个 `in_progress` 的规则。
- `known` 与 `unknown` 都是完整替换的字符串数组，而不是增量补丁。
- 每个数组最多 10 项；每项必须是去除首尾空白后的非空短句。
- 旧版只包含 `todos` 的快照仍然有效，前端将其解析为两个空知识列表。
- 失败、格式错误、子 Agent 或嵌套的 `todo_write` 不得替换当前主会话快照。

采用同一快照而不是分析聊天文本，能避免前端把推测误判成事实，也保证待办、已知和未知来自同一次 Agent 状态更新。

## 实时更新规则

Agent 在受管理的多步骤学术咨询中，必须在以下事件后重新提交完整快照：

- 用户提供会影响当前目标的新信息；
- `ask` 交互得到用户答案；
- 学术数据工具成功返回新证据；
- 工具返回空结果、失败或需要登录、配对、授权；
- 待办项开始、完成或被新的步骤替代；
- 最终答复前完成咨询状态核对。

更新时遵循以下迁移规则：

- 用户明确陈述的事实可以进入“已知内容”，但需要保留必要的主语和时间范围。
- 成功工具结果中与当前目标直接相关的客观事实可以进入“已知内容”。
- 推测、常规经验、失败查询和空结果不得进入“已知内容”。
- 根据当前已知内容、未完成待办和其他成功证据，持续重新判断哪些信息仍会实质影响结论，并更新“未知内容”。
- 某个未知项获得可靠答案后，将其从“未知内容”移除；如果答案与当前目标相关，再用确定性表述加入“已知内容”。
- 某个未知项不再影响当前结论时直接移除，不保留无关问题。
- 工具失败本身可以改变下一步待办，但不把错误文本当作学生事实。需要用户采取的动作可以被概括为未知条件，例如“尚未取得 Schedule Builder 登录后的实时课位数据”。
- 不展示内部提示词、思考过程、本地路径、数据库错误堆栈、凭据或 API Key。

## 状态生命周期

- 咨询快照以当前聊天为作用域，不跨聊天、项目或标签页复用。
- 重新打开历史聊天时，从最近一次成功的顶层 `todo_write` 恢复三块内容。
- 新的受管理咨询第一次写入完整快照时，替换上一轮咨询的三块内容，避免旧目标的事实和问题残留。
- 主机自动推进待办状态时必须保留同一快照中的 `known` 与 `unknown`，不能用只含 `todos` 的事件覆盖知识状态。
- 用户主动关闭侧栏只影响显示状态，不删除聊天历史中的咨询快照。

## 组件边界

- `todo_write` 后端工具负责 schema、数量、空白项和待办状态校验。
- 共享证据与 Agent 状态负责保存完整咨询快照，并在主机自动推进待办时一并重发知识列表。
- 前端解析层负责从最新有效事件构造 `ConsultationSnapshot`，不负责推理事实。
- `TodoRail` 只负责三段式渲染、收起/关闭和滚动定位，不分析聊天消息或工具输出。
- 国际化词典负责三个标题、空状态和无障碍标签。

## 错误与兼容处理

- 最新调用仍在运行且参数合法时，前端立即显示它，使状态更新与聊天执行过程同步。
- 最新调用失败或参数非法时，保留上一个有效快照。
- 历史数据只有待办时正常显示待办，并为另外两块显示空状态。
- 过长或数量超限的知识列表由工具拒绝，Agent 根据 schema 重新提交精简版本。
- UI 不渲染原始 JSON、工具错误或无法解析的内容。

## 测试与验收

- Go 单元测试覆盖扩展 schema、知识数组校验、旧 payload 兼容，以及自动推进待办时知识字段不丢失。
- 前端单元测试覆盖最新快照选择、运行中更新、失败回退、嵌套调用隔离和旧 payload 兼容。
- 组件契约测试覆盖三个区域、双语文案、空状态、数量标记、完成后仍可查看知识内容。
- 回归测试确认待办状态仍与聊天窗口同步，右侧栏仍位于聊天区域之外，窄窗口下仍可收起。
- 打包前运行相关 Go 与前端测试、前端构建和 Wails macOS 构建；随后重新生成 DMG 并校验签名、挂载内容与 SHA-256。

验收场景：用户提出多步骤选课问题后，右侧待办开始执行；用户回答课程偏好后，该答案出现在“已知内容”，对应问题从“未知内容”消失；工具成功返回课程信息后新增已知项；尚未确认且会改变推荐的先修课或时间限制继续保留在“未知内容”；三块内容和待办状态在每次更新后保持一致。
